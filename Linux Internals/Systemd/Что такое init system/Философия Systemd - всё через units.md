#sr-due 
Вся система описана юнитами - декларативными объектами. Главная идея: состояние системы = сумма активных юнитов, а не набор несвязанных скриптов.
- service - демоны/службы (как запускать, когда готов, что считать успехом)
- socket - сокеты/порт-триггеры для ленивой активации соответствующих сервисов
- timer - расписания (триггеры во времени) для сервисов
- path - файловые тригеры (изменился/появился путь -> запустить сервис)
- target - логические срезы состояния (аналог runlevels): multi-user, graphical, rescue и пр.
- (также mount/automount, device, slice/scope - но ключ в философии: любой аспект системы оформлен юнитом)
Следствия философии:
- Декларативность вместо процедурных скриптов: меньше скрытой логики, проще анализ зависимостей
- Активация по событию вместо "всё стартуем всегда": быстрее, стабильнее, экономнее
- Управление жизненным циклом (restart policies, sandboxing, ресурсы) - часть описания юнита, а не внешних костылей
