#sr-due 
- Параллелизм по зависимостями: строит граф, запускает максимально параллельно, сокращая boot-time
- Явные зависимости: Requires/Wants/Before/After/PartOf -> детерминированный порядок без магии в скриптах
- Socket Activation: PID 1 предварительно слушает сокеты и будит сервис по первому запросу;  повышает надёжность (нет гонок кто раньше поднялся), ускоряет загрузку (ленивая инициализация)
- Точная готовность: протокол уведомления (Type=notify/sd_notify) -> init знает когда сервис реально готов, а не просто запущен
- cgroups-учёт процессов: отслеживает все порождённые потомки сервиса, а не один PID -> корректные стоп рестарт ограничения ресурсов
- Единый формат и инструментарий: один синтаксис unit-файлов и одна CLI для всех типо юнитов -> низкий порог сопровождения
