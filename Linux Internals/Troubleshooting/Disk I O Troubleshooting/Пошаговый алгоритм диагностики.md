#sr-due 
Загрузка дисков и латентность:
```bash
iostat -xz 1 5
```
Виновники по процессам
```bash
sudo iotop -oP -d 1 -k
```
Корреляция с CPU/сетью/кэшем
```bash
dstat -cdngy --disk-util 1
```
### Шаг 1 — интерпретация
- `await` ↑ и `%util≈100` → диск забит; смотри `avgqu-sz`.
- `avgqu-sz` стабильно высокий → saturation.
- В `iotop` один PID пишет/читает “всё” → точечная оптимизация; много PID → конкуренция.

### Шаг 2 — локализация виновников
- В `iotop` и `lsof` увидел директории/файлы?
    - Логи: проверь уровень логирования/ротацию.
    - БД: проверь медленные запросы, индексы, параметры wal/journal.
    - Бэкапы: окно запуска пересмотри, ограничь скорость.

### Шаг 3 — проверка железа
- `smartctl -H/-a` → ошибки, ремапы, деградация → план замены.
- На RAID/SAN: запроси health с уровня контроллера/массива.
