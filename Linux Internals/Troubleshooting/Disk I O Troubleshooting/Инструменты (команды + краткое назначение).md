### iostat - панель дисковых метрик (из sysstat): IOPS/MB/s/latency/queue/util

Зачем: быстро понять, кто и как нагружает диск, увидеть latency и saturation.
```bash
iostat -xz 1
# -x: extended (await, svctm, avgqu-sz, util)
# -z: hide zero-activity devices
# 1 : обновлять каждую секунду
```
Ключевые поля:
- `r/s`,`w/s` (IOPS), `rkB/s`,`wkB/s` (пропускная),
- `await` (средняя латентность, мс),
- `avgqu-sz` (глубина очереди),
- `%util` (занятость).

### iotop - "top" для диска: кто сейчас читает или пишет
Зачем: увидеть виновников по процессам (real-time)
```bash
sudo iotop -oPa
# -o: только процессы с I/O
# -P: показывать per-process (не per-thread)
# -a: сбор суммарных байт (total) с начала запуска iotop
```
Смотри поля `DISK READ`, `DISK WRITE` и PID/команду.

### lsof — кто держит файл/устройство открытым
Зачем: найти, какие процессы читают/пишут конкретные файлы/точки монтирования.
```bash
sudo lsof +D /var/log | head
# +D <dir>: рекурсивно по каталогу (осторожно: дорого на больших деревьях)
sudo lsof | grep deleted
# процессы, удерживающие удалённые (deleted) большие файлы → заполнение FS
```

### dstat — комбинированная телеметрия I/O/CPU/сеть в одной ленте
Зачем: удобно **коррелировать** дисковые всплески с CPU/сетью
```bash
dstat -cdngy --disk-util --fs --output /tmp/dstat.csv 1
# -c: CPU, -d: disk, -n: net, -g: page cache, -y: sys
# --disk-util: %util по дискам, --fs: состояние ФС
# --output: сохраняет в CSV для последующего анализа
```
### smartctl — здоровье диска (S.M.A.R.T.)
Зачем: диагностировать аппаратные проблемы/предаварийные статусы.
```bash
sudo smartctl -H /dev/sdX          # краткий health
sudo smartctl -a /dev/sdX          # все атрибуты/логи ошибок
sudo smartctl -t short /dev/sdX    # короткий self-test (несколько минут)
```
Смотри: Reallocated_Sector_Ct, Pending_Sector, Media_Wearout, CRC Errors.
