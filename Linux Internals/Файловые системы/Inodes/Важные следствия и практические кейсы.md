#sr-due 
### A) **Hard link** vs **symlink**

- **Hard link**: ещё одно **имя** того же inode (та же «сущность», тот же `stat(2)`). Работает **только в пределах одной ФС**, нельзя на каталог (обычно запрещено). Удаление любого имени уменьшает link count, данные остаются пока счётчик > 0 **или** файл открыт процессом.  
    Команды: `ln file file2`; проверка: `ls -li` (одинаковый inode).
    
- **Symlink**: отдельный inode типа `l`, чьи данные = **строка-путь** к цели. Может указывать через ФС и на каталоги, разрывается при удалении цели.  
    Команды: `ln -s target link`; `stat link` (про ссылку) vs `stat -L link` (по цели).
    

### B) **Удаление «открытого» файла**

Если процесс держит **открытый FD**, и вы сделали `rm` (link count → 0), inode остаётся в системе как «анонимный» до закрытия FD. Типичный случай: лог-файлы → место не освобождается.  
Диагностика:
```bash
lsof | grep '(deleted)'
```
Фикс: перезапуск процесса или `: > /proc/<pid>/fd/<n>` (обнулить).

### C) **rename — атомарный**

Переименование меняет **каталожную запись** (имя→inode), сам inode не меняется; `mv` в пределах одной ФС — атомарная операция.

### D) **Исчерпание inodes**

Можно «закончить» **inodes** раньше, чем место по байтам (много мелких файлов).  
Проверка: `df -i`. Фикс: пересоздать ФС с большим числом inodes или объединять мелочь (архивы/БД/dirent-стратегии).

### E) **ctime ≠ creation time**

`ctime` меняется при **любой** правке метаданных/данных. Не путать с «созданием». Для реального «когда создан» — зависит от ФС/инструментов (на ext4 можно увидеть `Birth:` в `stat` — не всегда).
