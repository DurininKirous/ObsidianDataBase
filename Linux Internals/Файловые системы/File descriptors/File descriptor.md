#sr-due 
### База
- FD - это целое число в процессе, указывающее на запись в таблице открытых файлов (per-process -> open-file table -> inode)
- Стандарты:
	- 0 -> stdin
	- 1 -> stdout
	- 2 -> stderr
	- 3+ -> любые открытые файлы/сокеты/каналы
Типы объектов за FD: обычные файлы, каталоги, **сокеты** (TCP/UDP/Unix), **пайпы** (`pipe`), **FIFO**, **eventfd**, **inotify**, **timerfd**, устройства из `/dev/*`.

## Важные различия (термины ядра)
- **Descriptor (число в процессе)** → указывает на
- **Open file description** (ядровая запись: файл + позиция + флаги `O_APPEND/O_NONBLOCK/…`) → указывает на
- **inode** (метаданные, права, дисковый объект).

Из-за этого:
- `dup()`/`dup2()`/`dup3()` создают **второй FD**, _разделяющий одну_ open-file запись (общая позиция чтения/записи).
- `fork()` копирует таблицу FD: ребёнок видит те же описания; `execve()` по умолчанию **сохраняет** FD, _кроме_ тех, что помечены **CLOEXEC**.
