#sr-due 
**`exec*()`** - в текущем процессе _заменяет_ код/данные на новый исполнимый образ (ELF/скрипт).
**Главное:** `execve(path, argv, envp)` _никогда не возвращается_ при успехе — текущий процесс превращается в другую программу; PID сохраняется.

**Семейство:**
- `execl`, `execle`, `execlp`, `execv`, `execvp`, `execvpe` → удобные обёртки.  
    Суффикс **p** — ищет в `PATH`, иначе путь должен содержать `/`. Суффикс **e** — задаёт своё `envp`.

**Что происходит внутри (упрощённо):**
1. Ядро валидирует бинарь/скрипт.
2. Для ELF — маппит сегменты `PT_LOAD`, настраивает стек (argv/envp/auxv), **ASLR**, регистры; указывает entry point.
3. Для скриптов `#! /path/to/interpreter args` — ядро вызывает интерпретатор с подменённым `argv`: `[interpreter, args..., script, rest_argv...]`.
4. Запускается **динамический линкер** (`ld.so`) если ELF динамически связан: резолвит `DT_NEEDED`, маппит so, применяет релокации, запускает `init`-конструкторы, затем `main`.

**Наследование и сбросы при `exec`:**
- **Сохраняется:** PID, PGID/сессия, _открытые дескрипторы без_ `FD_CLOEXEC`, текущий каталог, `umask`, ресурсные лимиты, _часть_ сигналов (но все обработчики сигналов, установленные `sigaction`, сбрасываются в `SIG_DFL`, кроме тех, что игнорировались — остаются игнорируемыми).
- **Сбрасывается/очищается:** адресное пространство старой программы, все маппинги, перехватчики сигналов, «внутренности» libc, треды — **исчезают** (после `exec` остаётся один поток).
- **Права и привилегии:**
    - `setuid/setgid` биты в ELF/скриптах (через интерпретатор редко-когда реально работают для скриптов).
    - `no_new_privs` (через `prctl`) запрещает повышать привилегии при `exec`.
    - Capabilities: при `exec` пересчитываются по правилам ambient/permitted/inheritable + securebits.
    - Безопасность окружения: динамический линкер отфильтрует часть переменных для setuid-бинарей.
