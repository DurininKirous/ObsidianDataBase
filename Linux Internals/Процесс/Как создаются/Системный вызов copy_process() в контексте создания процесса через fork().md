### 💡 The What
*Что это?*
Этот системный вызов выполняет всю основную работу в контексте создания процесса через fork() системные вызовы.

### ⚙️ The Why & How
*Инженерная суть. Механика. Зачем это нужно?*
По достижении этого вызова при создании процесса данный системный вызов делает следующее:
- copy_process() через dup_task_struct() создает новый системный стек ядра, структуры thread_info и task_struct для нового процесса, которые идентичны родительскому процессу
- Поля новых структур в основном очищаются для подготовки места новым данным
- Далее дочерний процесс переводится в состояние UNINTERRUPTIBLE_SLEEP, чтобы он случайно не начал выполняться
- Вызывается функция copy_flags(), которая копирует обновляет значение поля flags структуры task_struct
- Вызывается функция alloc_pid(), которая выдает новому процессу его уникальный PID
- Далее в зависимости от флагов копируются разные данные из родительского процесса в дочерний
После выполняется возврат в функцию do_fork(), дочерний процесс в случае успеха размораживается и запускается. Ядро намеренно это делает, чтобы например в случае вызова exec сразу после запуска процесса избежать издержек, связанными с использованием механизма копирования данных при записи. Эти издержки неизбежно возникают, если родительский процесс начинает выполняться первым и что-то записывает в свое адресное пространство
