#sr-due 
nice - желательность для CFS соединений. Меньше значение -> более агрессивное получение CPU.
В `top`/`ps`:
- `NI` — nice; `PR` — приоритет, вычисляется из класса. Для CFS `PR` ≈ `20 + NI` (показывается около `80`/`120` в разных утилитах, не путать с RT-prio).
- Для RT — `PR` фиксируется как `rt`/число (0..99), **не зависит** от nice.
Под капотом CFS использует **веса**: каждому nice соответствует «weight» (экспоненциальная шкала). Относительная доля CPU ≈ weight(А)/Σweight.
Доп. политики CFS:
- **SCHED_BATCH** — для бэчевых джоб: меньше влияния на интерактивность.
- **SCHED_IDLE** — «наименьший приоритет»; работает, когда CPU простаивает.
