# A. Базовые понятия процесса

1. **Процесс vs поток.** Процесс — выполняющийся экземпляр программы со своим адресным пространством и ресурсами (FD, UID/GID, сигналы, cwd/umask, таймеры, cgroups/NS). Поток — «лёгкая задача» внутри процесса: делит память/FD с другими потоками, имеет свой стек и контекст CPU.
    
2. **Что принадлежит процессу.** Виртуальная память (code/data/bss/heap/stack/mmap), таблица файловых дескрипторов, права (UID/GID/capabilities), текущий каталог и umask, маски/обработчики сигналов, таймеры, rlimits, cgroups, namespaces, приоритет/политика планирования.
    
3. **Жизненный цикл.** `fork()/clone()` → (опц.) `exec*()` заменяет образ → выполнение → `exit()`/сигнал → состояние **zombie** (только запись в таблице) → родитель делает `wait*()` и «снимает» зомби. Сироту усыновляет PID 1 и тоже «reap»-ит.
    

# B. Память процесса

4. **Layout.** text (код), data (иниц. глобальные), bss (неиниц. глобальные, обнулены), heap (динамика, `brk/mmap`), mmap-сегменты (so/файлы/анон), stack (кадры вызовов, по одному на поток).
    
5. **ASLR и CoW.** ASLR — рандомизация баз адресов (сложнее эксплойтить). Copy-On-Write — страницы копируются физически только при записи (ускоряет `fork`). ASLR — это защитная техника, при которой **базы ключевых участков адресного пространства процесса случайно сдвигаются при каждом запуске**. Идея: злоумышленник не знает точных адресов кода/данных → труднее сделать ret2libc/ROP и другие атаки, зависящие от фиксированных адресов.
    
6. **VmSize vs VmRSS vs PSS.** VmSize — общий объём виртуальных маппингов. VmRSS — реально резидентные страницы процесса. PSS — «пропорциональный» RSS: shared-страницы делятся между процессами (есть в `smaps`).
    

# C. Идентификаторы и состояния

7. **PID/PPID/TGID.** PID — идентификатор задачи; PPID — PID родителя; TGID — ID группы потоков (для главного потока совпадает с PID). Если родитель умер — PPID становится 1 (systemd).
    
8. **Состояния.** R — выполняется/готов; S — прерываемый сон; D — непрерываемый I/O-сон; T — остановлен (`STOP`/отладчик); Z — зомби (ждёт `wait`).
    
9. **Ликвидация зомби и D-state.** Зомби «снимается» родителем через `wait*()` (сигналами не убивается). D-state — ядро ждёт I/O; лечится устранением причины (диск/NFS/драйвер), а не сигналами.
    

# D. Дерево процессов и шелл

10. **Дерево и PID 1.** Все процессы — потомки PID 1 (`systemd`): он усыновляет сирот и «reap»-ит их, запускает/следит за сервисами, может пересылать сигналы.
    
11. **Как bash запускает команду.** Разбор → если не builtin: `fork()` → (в child) PGID/редиректы/env/rlimit/umask → `execve()` нового образа; родитель ждёт (foreground) или нет (background).
    
12. **Пайпы `A|B|C`.** Создаётся N−1 pipe’ов → каждый этап `fork()` → в child `dup2()` stdin/stdout на нужные концы → `execve()`; родитель закрывает лишние концы, опционально ждёт группу.
    

# E. fork/exec/wait/exit

13. **Что копирует `fork()`.** Таблицы и дескрипторы наследуются по ссылке (позиции файлов shared), адресное пространство помечается CoW (реально не копируется до записи), наследуются сигнальные маски/обработчики, cwd/umask, но PID/PPID новые.
    
14. **Что делает `exec*()`.** Полностью заменяет адресное пространство новым образом (ELF/скрипт), сохраняет PID/PGID/SID, закрывает FD с `CLOEXEC`, сбрасывает обработчики сигналов в default (игноры сохраняются), перезагружает права (setuid, capabilities). Потоки исчезают — остаётся один.
    
15. **`exit()` vs `_exit()`.** `exit()` вызывает `atexit()`, чистит stdio и только потом syscall `_exit()`. `_exit()` идёт сразу в ядро — использовать в child после `fork()` (если нет `exec`), чтобы не дублировать аtexit/буферы.
    
16. **Правильный `wait`.** Либо обрабатывать `SIGCHLD` и в обработчике крутить `while (waitpid(-1,&st,WNOHANG)>0)`, либо периодически вызывать `waitpid`. Так забираются все дети, исключаются висящие зомби.
    

# F. Сигналы

17. **Чем отличаются.** SIGTERM — корректное завершение; SIGINT — Ctrl+C; SIGKILL — немедленное убийство (неловим); SIGHUP — обрыв TTY/обычно reload; SIGSTOP/SIGCONT — останов/продолжение (STOP неловим).
    
18. **Перехват.** Использовать `sigaction`; в handler’е только async-signal-safe операции (например, `write`, флаги `sig_atomic_t`). Часто ставят `SA_RESTART`.
    
19. **После `exec()`.** Все обработчики сбрасываются в default; игнор статуса некоторых сигналов сохраняется.
    
20. **RT-сигналы.** `SIGRTMIN..SIGRTMAX`: очередятся, доставляются в порядке номеров, можно передавать payload (`sigqueue`). Подходят для событий, где важен порядок и отсутствие потерь.
    

# G. /proc

21. **Ключевые узлы.** `status` (сводка: state, VmRSS, Threads, Cap*), `cmdline` (argv, NUL-раздел), `environ` (переменные, NUL-раздел), `fd/` (открытые файлы/сокеты), `maps`/`smaps(_rollup)` (маппинги/память), `limits` (rlimits), `io` (I/O-счётчики), `sched` (планировочные).
    
22. **Почему NUL и кто читает.** Чтобы однозначно хранить строки с пробелами; читать может владелец процесса и root (ограничения LSM/ptrace_scope возможны).
    
23. **meminfo/cpuinfo/loadavg.** `meminfo` — агрегаты памяти системы; `cpuinfo` — логические CPU, флаги, модель; `loadavg` — среднее количество runnable+uninterruptible задач за 1/5/15 мин.
    
24. **PSI.** `/proc/pressure/{cpu,io,memory}` — доля времени под «давлением» (stall). Полезно для алертов/автотюнинга (лучше отражает проблемы, чем load).
    

# H. Планировщик и приоритет

25. **Классы.** CFS (`SCHED_OTHER/BATCH/IDLE`) — дефолт, делит CPU по весам (nice). RT (`SCHED_FIFO/RR`) — выше CFS, приоритеты 0..99. Deadline (`SCHED_DEADLINE`) — EDF/CBS с `(runtime, period, deadline)`.
    
26. **nice.** Диапазон −20..+19; меньше значение → больше вес в CFS → больше доля CPU. На RT не влияет. В cgroup v2 есть `cpu.weight` (1..10000).
    
27. **CPU affinity.** Набор CPU, на которых задача может работать. Смотреть/менять: `taskset -p`, `/proc/<pid>/status`→`Cpus_allowed_list`, `sched_setaffinity()`.
    
28. **Load average.** Считает R+D задачи. На N-ядрах «load≈N» — CPU насыщен; высокий load при низком %CPU → I/O-пробки (D-state).
    
29. **per-CPU очереди.** На каждом CPU свой `rq`. Порядок: stop > deadline > RT > CFS > idle. Внутри: RT — bitmap+списки по приоритетам; CFS — rb-tree по `vruntime`; deadline — rb-tree по дедлайну.
    

# I. Практика и диагностика

30. **pgrep vs pidof vs ps|grep.** `pgrep` — гибкий поиск PID по имени/regex (`-f` — по cmdline); `pidof` — PID исполнимого; `ps|grep` — универсально, но шумно (и захватывает сам `grep`).
    
31. **Утечки FD и `CLOEXEC`.** Смотри `/proc/<pid>/fd` и `lsof -p <pid>`. Ставь `FD_CLOEXEC`/`O_CLOEXEC`, чтобы FD не утекали через `exec`.
    
32. **Context switches.** `pidstat -w 1 -p <PID>` (voluntary/nonvoluntary), `/proc/<pid>/status` (соответствующие счётчики).
    
33. **CPU vs I/O узкое место.** CPU-бутылочное: высокий `%CPU`, `r` в `vmstat`, низкий `await` в `iostat`. I/O-бутылочное: высокий `D`, большой `await`/`%util` дисков, высокий load при невысоком `%CPU`; смотри `iostat -xz`, `pidstat -d`, `/proc/pressure/io`.
    
34. **Стратегия остановки.** Сначала `SIGTERM` (graceful) → подождать таймаут → `SIGKILL` как крайняя мера. Логику shutdown делай идемпотентной.
    

# J. Безопасность и привилегии

35. **Права для планировщика.** Менять RT/deadline и снижать nice < 0 может только root или процесс с `CAP_SYS_NICE`.
    
36. **`no_new_privs`, setuid, caps.** `no_new_privs=1` запрещает повышать привилегии при `exec` (setuid/caps не поднимут права). При `exec` вычисляются наборы capabilities (permitted/effective/ambient) по правилам ядра.
    
37. **`PR_SET_PDEATHSIG`.** В дочернем процессе `prctl(PR_SET_PDEATHSIG, SIGTERM)` — если родитель умрёт, ядро пришлёт сигнал ребёнку (упрощает уборку «прилипших» воркеров).
