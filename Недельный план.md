## Системный дизайн
**Теория (2.5 часа)**
**Ключевые концепции:**
- **CAP теорема** - глубокое понимание, не просто "consistency, availability, partition tolerance"
    - Почему можно выбрать только 2 из 3
    - Примеры систем: CP (MongoDB, HBase), AP (Cassandra, DynamoDB), CA (традиционные RDBMS в одном ДЦ)
    - Как реальные системы балансируют между C и A
- **PACELC теорема** - расширение CAP для реального мира
    - Если есть Partition: выбор между A и C
    - Else (нормальная работа): выбор между Latency и Consistency
- **Consistency Models:**
    - Strong consistency (linearizability)
    - Sequential consistency
    - Causal consistency
    - Eventual consistency
    - Read-your-writes consistency
    - Monotonic reads/writes
- **Время в распределённых системах:**
    - Проблема синхронизации часов
    - Logical clocks (Lamport timestamps)
    - Vector clocks
    - Hybrid logical clocks (HLC)

**Задание 1: CAP в действии**
Спроектируй на бумаге 3 версии simple key-value store:

```
Version 1 (CP):
Client → [Master Node] → [Replica 1, Replica 2]
         └─ Синхронная репликация (wait for all replicas)
         └─ Если replica недоступна → reject writes
         
Анализ:
- Consistency: ✅ Всегда читаем последнюю запись
- Availability: ❌ Недоступны при partition
- Partition tolerance: ✅ Определяем что есть partition

Version 2 (AP):
Client → [Node 1, Node 2, Node 3] (peer-to-peer)
         └─ Асинхронная репликация
         └─ Accept writes на любую ноду
         └─ Eventual consistency через gossip protocol
         
Анализ:
- Consistency: ❌ Можем читать stale data
- Availability: ✅ Всегда принимаем запросы
- Partition tolerance: ✅ Работаем при partition

Version 3 (CA - не реально для распределённой системы):
Client → [Single Database]
         └─ Нет партиций, один узел
```

Для каждого варианта опиши:
- Что произойдёт при network partition
- Сценарии конфликтов при concurrent writes
- Как система восстанавливается после partition

## Месяц 1: Ядро и управление памятью (4 занятия)

### Занятие 1: Архитектура ядра Linux глубоко (4-5 часов)

**Теория (2.5 часа)**

**Kernel Space vs User Space - детально:**

```
Memory Layout (x86_64):

User Space:    0x0000000000000000 - 0x00007FFFFFFFFFFF (128TB)
Kernel Space:  0xFFFF800000000000 - 0xFFFFFFFFFFFFFFFF (128TB)

Разделение защищено CPU (Ring 0 vs Ring 3):
- Ring 0 (Kernel mode): полный доступ к hardware, все инструкции
- Ring 3 (User mode): ограниченный доступ, нет прямого доступа к hardware

Переход User → Kernel:
1. System call (int 0x80 / syscall instruction)
2. Hardware interrupt
3. Exception (page fault, divide by zero)
```

**System Call механизм глубоко:**

````c
// User space code
int fd = open("/etc/passwd", O_RDONLY);

// Что происходит под капотом:

1. libc обёртка (glibc):
   - Подготавливает аргументы
   - Загружает syscall number в регистр (RAX на x86_64)
   - Выполняет syscall instruction

2. CPU переключается в kernel mode:
   - Сохраняет user space регистры
   - Переключает стек на kernel stack
   - Передаёт управление kernel

3. Kernel обработка:
   entry_SYSCALL_64()  // arch/x86/entry/entry_64.S
      ↓
   do_syscall_64()
      ↓
   sys_call_table[syscall_number]  // syscall dispatch table
      ↓
   SYSCALL_DEFINE3(open, ...)  // fs/open.c
      ↓
   do_sys_open()
      ↓
   // Real work: path lookup, permissions check, etc.

4. Возврат в user space:
   - Результат в RAX
   - Восстанавливаются регистры
   - sysret instruction
```

**Kernel Components детально:**

1. **Process Scheduler (CFS - Completely Fair Scheduler):**
```
Каждый процесс имеет:
- vruntime (virtual runtime) - сколько CPU времени получил
- nice value (-20 to +19) - приоритет
- weight - вычисляется из nice

CFS алгоритм:
1. Хранит процессы в red-black tree
2. Ключ - vruntime
3. Выбирает leftmost node (минимальный vruntime)
4. Запускает процесс на time slice
5. После выполнения: vruntime += actual_runtime * (1024 / weight)
6. Процесс перемещается в дереве
7. Повтор

Пример:
Process A: nice=0, weight=1024, vruntime=1000ms
Process B: nice=5, weight=335, vruntime=1000ms

Time slice: 6ms (типичное значение)

A выполняется 6ms:
vruntime_A = 1000 + 6 * (1024/1024) = 1006ms

B выполняется 6ms:
vruntime_B = 1000 + 6 * (1024/335) = 1018ms

→ A получит CPU снова (меньший vruntime)
```

2. **Memory Management Unit (MMU):**
```
Virtual Memory → Physical Memory translation

Page Table hierarchy (x86_64, 4-level):

Virtual Address (48 bits):
[PML4 index|PDP index|PD index|PT index|Offset]
   9 bits    9 bits   9 bits   9 bits  12 bits

Translation:
1. CR3 register → PML4 base address
2. PML4[index] → PDP address
3. PDP[index] → PD address
4. PD[index] → PT address
5. PT[index] → Physical page frame
6. Physical address = frame + offset

Кэширование: TLB (Translation Lookaside Buffer)
- Hardware cache для page table entries
- Типично: 64-512 entries
- Flush при context switch
```

3. **Virtual File System (VFS) - абстракция над всеми FS:**
```
VFS objects:

superblock - представляет mounted filesystem
├── inode - представляет file/directory
│   ├── dentry - directory entry (name → inode mapping)
│   └── file - открытый файл (fd)

Операции:
struct inode_operations {
    int (*create) (struct inode *, struct dentry *, umode_t, bool);
    struct dentry * (*lookup) (struct inode *, struct dentry *, unsigned int);
    int (*link) (struct dentry *, struct inode *, struct dentry *);
    int (*unlink) (struct inode *, struct dentry *);
    // ... много других
};

struct file_operations {
    ssize_t (*read) (struct file *, char __user *, size_t, loff_t *);
    ssize_t (*write) (struct file *, const char __user *, size_t, loff_t *);
    int (*open) (struct inode *, struct file *);
    int (*release) (struct inode *, struct file *);
    // ... и т.д.
};

Каждая FS (ext4, xfs, btrfs) реализует эти операции
````

**Задание 2: Напиши минимальную программу с inline syscall**

```c
// syscall_demo.c - без libc
#define _GNU_SOURCE
#include <unistd.h>
#include <sys/syscall.h>

// Manual syscall без libc wrapper
ssize_t my_write(int fd, const void *buf, size_t count) {
    long ret;
    asm volatile (
        "syscall"
        : "=a" (ret)
        : "a" (__NR_write), "D" (fd), "S" (buf), "d" (count)
        : "rcx", "r11", "memory"
    );
    return ret;
}

int main() {
    const char msg[] = "Hello from raw syscall!\n";
    my_write(1, msg, sizeof(msg) - 1);
    return 0;
}
```
