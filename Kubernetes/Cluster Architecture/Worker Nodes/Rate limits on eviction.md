По умолчанию скорость процесса выселения подов из недоступных нод имеет скорость, равную флагу *--node-eviction-rate* кжаду секунду, по умолчанию равную 0.1, что означает, что каждые 10 секунд сценарий применяется к одной ноде.
Поведение сценария выселения подов с нод меняется в зависимости от количества нод с *.status* *Unknown* и *Failure* в один момент в случае если кластер находится в облаке:
	1. Если процент количества таких нод как минимум равно параметру *--unhealthy-zone-threshold*, по умолчанию равного 0.55, то скорость выселения подов с ноду уменьшается
	2. Если кластер маленький, то есть количество нод меньше или равно *--large-cluster-size-threshold*, по умолчанию равного 50, то все выселения прекращаются и не применяются
	3. В остальных случаях скорость выселения уменьшается до *--secondary-node-eviction-rate* и равн по умолчанию 0.01 ноде в секунду. 
Причина по которой есть такие правила заключается в том, что может случится так, что одна зона доступности может стать отделена от Control Plane, пока другие соединены. Если кластер не охватывает несколько зон доступности облачных провайдеров, то механизм выселения не учитывает недоступность на зону.
Ключева причина распределения нод между разными зонами заключается в том, что в случае полного падения одной зоны, рабочую нагрузку можно переместить в другую. Также если некоторые ноды становятся недоступны в одной зоне, начинается процесс выселения их и отправки в здоровую зону. Если все зоны нездоровы и нет нод, то node controller считает, что это скорее проблемы с соединением между control plane и зонами с нодами, поэтому выселение не происходит.
Node controller также ответственен за то, чтобы выселять поды с нод, которые отмечены как *NoExecute* с помощью *[[taints]]*, пока оно не будет снято.
Node Controller  также добавляет taints нодам в зависимости от их состояния: unreachable, not ready. То есть scheduler не будет размещать ноды там
