#sr-due 
LB вычисляет хеш от IP клиента и отправляет на конкретный сервер:
```
hash(client_ip) % num_servers = server_index
```

Пример:
- CLient A (IP 1) -> hash -> всегда Servver 1
- Client B (IP 2) -> hash -> всегда Server 3

Зачем это нужно?
- Session stickiness: если на сервере хранится сессия пользователя
- Cache locality: если у каждого сервера свой локальный кеш

Проблема: Что если добавили Server 4? Клиенты будут распределяться ведь по другому из-за другого количество серверов теперь. Все кеши станеут неактуальными

Решение: Consistent Hashing
- Серверы и клиенты размещаются на "кольце"
- При добавлении сервера перераспределяется только ~1/N трафика
- Используется в Redis Cluster, Cassandra, DynamoDBт
