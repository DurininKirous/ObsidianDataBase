#sr-due 
IP (L3)
- Обеспечивает адресацию и маршрутизацию (best-effort)
- Пакеты могут теряться, дублироваться, приходить не по порядку
- MTU (обычно 1500 байт на Ethernet) -> фрагментация нежелетальна (дорого, ломает производительность)
TCP (L4, поток байт)
- Надёжность и порядок: ACK, ретрансляции, контроль окна.
- 3-way handshake: SYN-SYN/ACK-ACK = 1RTT до полезных данных
- Congestion Control: ограничивает скорость, чтобы не задавить сеть; важен slow-start -> окно растёт экспоненциально, затем линейно
- Head-of-line blocking: потеря одного сегмента останаваливает весь поток, пока не дойдёт ретрансляция.
- Nagle / Delayed ACK: уменьшает число мелких пакетов ценой задержки (Для RPC часто включают TCP_NODELAY)
Когда брать: API, базы, всё, где важна корректность и упорядоченность

UDP (L4, датаграммы)
- Нет соединения, нет гарантии доставки/порядка/повторов
- Минимальная задержка, сохранены границы сообщений
- Требует ручной надёжности на уровне приложения
- Проблемы с NAT/Firewall решаются keep-alive, STUN/Turn
Когда брать: realtime, игры, телеметрия - где лучше потеря, чем лаг
