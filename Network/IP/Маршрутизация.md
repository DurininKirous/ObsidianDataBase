# Что это и как работает (суть)
- **Routing table** — набор правил «куда слать пакет» в зависимости от адреса назначения. Ядро выбирает маршрут по правилу **Longest Prefix Match (самый длинный префикс)**, а если равны — по **metric** (меньше = лучше).
- **Default gateway `0.0.0.0/0`** — «путь по умолчанию», когда нет более специфичного маршрута. Обычно выглядит как `default via <IP шлюза> dev <iface>`.

# Виды маршрутов

- **Local/connected (подключённые):** появляются, когда интерфейсу назначен адрес/подсеть. Идут **напрямую (on-link)**: ARP по адресу назначения, без шлюза.
- **Static routes (статические):** добавлены вручную (например, `10.0.0.0/8 via 192.168.1.254 dev eth0`). Простые, предсказуемые, но **не адаптируются** к сбоям.
- **Dynamic routes (динамические):** получаютcя от протоколов маршрутизации:
    - **RIP** — дистанционно-векторный, «хопы», простой, устаревающий.
    - **OSPF/IS-IS** — линк-стейт внутри автономной системы (IGP), быстрые конвергенция/восстановление.
    - **BGP** — междоменные маршруты (EGP), управляет обменом префиксами между AS, поддерживает политики.  
        Эти протоколы формируют/обновляют таблицу сами и часто назначают **metric/cost**.

# Metric (стоимость)
- Число «предпочтительности» маршрута **внутри одного источника** маршрутов (в Linux — `metric`, в OSPF — `cost`, в BGP — свои атрибуты). При одинаковой длине префикса побеждает **меньшая метрика**. Если ещё и метрика равна — возможен **ECMP** (балансировка по нескольким next-hop).
