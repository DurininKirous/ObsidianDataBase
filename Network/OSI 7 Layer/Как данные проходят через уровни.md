#sr-due 
Представим: клиент отправляет HTTP-запрос серверу.

**На стороне отправителя (сверху вниз):**  
1. **Application:** формируется HTTP-запрос.  
2. **Presentation:** при необходимости шифруется/кодируется (например, TLS для HTTPS).  
3. **Session:** отмечаются границы/контекст сессии.  
4. **Transport:** HTTP-данные упаковываются → TCP-сегмент (или UDP-датаграмма), добавляются номера **портов** (src/dst).  
5. **Network:** сегмент завернётся в IP-пакет: добавятся **IP-адреса** (src/dst), выберется маршрут.  
6. **Data Link:** пакет пойдёт в **Ethernet-кадр**: добавятся **MAC-адреса** ближайшего перехода (src MAC = нашего интерфейса, dst MAC = шлюза/следующего узла).
7. **Physical:** кадр превращается в **сигналы/биты** по кабелю/радио.
Краткая формула инкапсуляции (сверху вниз):
```scss
ДАННЫЕ → [TLS] → СЕГМЕНТ(TCP/UDP с портами) → ПАКЕТ(IP с IP-адресами) → КАДР(Ethernet с MAC) → БИТЫ(сигналы)
```

**На стороне получателя (снизу вверх — деинкапсуляция):**  
1 → 2: принимает биты, собирает **кадр**, проверяет его и, если **MAC dst = наш**, снимает заголовок канального уровня.  
2 → 3: извлекает **IP-пакет**, смотрит **IP dst** (если не наш — роутит дальше; если наш — вверх).  
3 → 4: передаёт **TCP/UDP**; TCP проверяет порядок/целостность, собирает байтовый поток.  
4 → 5/6/7: восстанавливается сессия, **расшифровка TLS**, приложение читает **HTTP**.

# Быстрые отличия устройств
- **Hub (L1):** тупо ретранслирует сигнал всем — коллизии, нет MAC-таблицы.
- **Switch (L2):** пересылает кадры по **MAC**, создаёт отдельные коллизионные домены.
- **Router (L3):** пересылает пакеты по **IP**, разделяет широковещательные домены.
