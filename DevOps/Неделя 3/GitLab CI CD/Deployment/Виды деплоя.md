#sr-due 

| Вид деплоя            | Что это                                                | Когда применять                           |
| --------------------- | ------------------------------------------------------ | ----------------------------------------- |
| **Direct / In-place** | Просто заменяем старую версию новой                    | Малые проекты, без downtime-критичности   |
| **Rolling**           | Пошагово обновляем инстансы (по 1, по 10%, ...)        | Стейджинг/прод, минимальный риск          |
| **Blue-Green**        | 2 окружения: переключаем трафик с "старого" на "новое" | Критичные проды, быстрый откат            |
| **Canary**            | Разворачиваем только для части пользователей           | Эксперименты, AB-тесты, прод на 1%        |
| **Shadow**            | Отправляем трафик в оба инстанса, но второй "в тени"   | Тестирование без воздействия              |
| **Recreate**          | Останавливаем старое, потом запускаем новое            | Примитивно, но быстро (Docker Compose)    |
| **GitOps**            | Деплой через git-коммиты и reconciliation              | Kubernetes, declarative IaC, high control |
