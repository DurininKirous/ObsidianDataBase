#sr-due 
cgroups v2 - эволюция cgroups v1, появившаяся в ядре Linux с версии ~4.5 и становящаяся дефолтом в современных дистрибутивах.
Почему сделали версию 2:
- Каждый контроллер имел свою иерархию директорий
- Конфигурация была сложной и часто неочевидной 
- Не все контроллеры могли быть активны в одной и той же cgroup
Cgroups v2 решают это:
- Теперь единая иерархия, все контроллеры активируются в одном дереве
- Более чистый и единообразный интерфейс
- Лучшая работа с PSI
### Основные элементы

| Компонент        | Для чего                                                                               |
| ---------------- | -------------------------------------------------------------------------------------- |
| Иерархия         | Единое дерево директорий в /sys/fs/cgroup. Там создаются папки - группы процессов      |
| Контроллеры      | Устанавливают лимиты и счётчики                                                        |
| Файлы управления | Через них читаются/устанавливаются лимиты, приоритеты, статистика                      |
| cgroup.procs     | В этот файл записывается PID процессов, который будут подчиняться правилам этой cgroup |
### Структура /sys/fs/cgroup
/sys/fs/cgroup
 ├── cgroup.controllers       # какие контроллеры вообще доступны в системе
 ├── cgroup.subtree_control   # активируем контроллеры для поддиректорий
 ├── cgroup.procs             # PIDs в этой cgroup
 ├── cpu.stat                 # статистика по CPU
 ├── memory.max               # лимит памяти
 ├── memory.current           # текущее использование памяти
 ├── io.max                   # лимиты на I/O
 ├── io.stat                  # статистика по I/O
 ├── ...                      # PSI и другие метрики
 ├── init.scope               # системная группа (PID 1 и основа всей системы)
 ├── system.slice/            # службы systemd
 └── user.slice/              # пользовательские процессы

Чтобы создать свою группу cgroups, достаточно создать папку в /sys/fs/cgroup, добавить параметры в cgroup.subtree_control для дочерних групп, закинуть нужные ограничения в саму группу, и потом создать файл cgroup.procs в папке, добавить туда PID нужные.
