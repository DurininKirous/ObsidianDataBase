Для того чтобы включить поддержку свопа в ноде, NodeSwap параметр должен быть включён в kubelet (по умолчанию включено), и  *--failt-swap-on* или failSwapOn параметр конфигурации должцы быть false (по умолчанию true). Для разрешения нодам утилизации своп памяти, swapBehavior не должно быть равно NoSwap (мо умолчанию true) в конфигурации kubelet.
Пользователь может опционально конфигурировать memorySwap.swapBehavior для определния как нода будет использовать своп память. Например, 
```
memorySwap:
	swapBehavior: LimitedSwap
```
NoSwap: (default) отключает поддержку свопа нодами
LimitedSwap: Утилизация своп памяти нодами для рабочей нагрузки подвергается ограничениям. Только подам класса [[*Burstable QoS*]] разрешается полностью использовать своп. 
Если memorySwap не определено, но NodeSwap включён, по умолчанию поведение будет NoSwap.
Если включено LimitedSwap, то подам которые не подпадают по классификацию Burstable QoS запрещается использовать Swap. Для поддержания безопасности и здоровья нод данным подам запрещено использовать память свопа при включённом параметре LimitedSwap.
Для последующего вычисления потребляемого количества Swap, надо определить следующие термины:
	1. nodeTotalMemory: Общее количество доступной для ноды памяти
	2. totalPodsSwapAvailable: Общее количество доступной памяти swap для использования подами.
	3. containerMemoryRequest: Запрос памяти контейнера.
Ограничение потребления своп определяется как: (3/1)*2.
Важно отметить, что для контейнеров класса BUrstable QoS можно отказаться от использования подкачки, указав запросы к памяти, которые соответствуют ограничениям памяти. Контейнеры, настроенные таким образом, не будут использовать swap память.
Swap поддерживается только при использовании cgroup v2, при использовании cgroup v1 swap не поддерживается.
