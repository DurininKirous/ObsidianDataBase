#sr-due 
1. **Service не отвечает**
- `kubectl get svc web -o wide` — убедись, что есть VIP/порты.
- `kubectl get endpointslices -l kubernetes.io/service-name=web -o yaml` — есть ли endpoints? (Пусто → проверь `selector` сервиса и **readiness** Pod’ов.)
- На ноде с клиентом:
    - iptables: `iptables -t nat -S | grep KUBE-SVC` (iptables-режим)
    - IPVS: `ipvsadm -Ln` (ipvs-режим)
- Проверь, доходит ли трафик до контейнера: `kubectl exec <pod> -- ss -tnlp`, `curl localhost:targetPort`.

2. **Потерялся IP клиента**
- Посмотри `externalTrafficPolicy` сервиса (NodePort/LB).
- Для сохранения IP: `externalTrafficPolicy: Local` + убедись, что запрос попадает на ноду с **локальным** endpoint.

3. **Pod сам себе по сервису не ходит**
- Hairpin NAT: проверь CNI/hairpin-настройки; некоторые плагины включают auto, иногда требуется ручной тюнинг.

4. **Headless/StatefulSet DNS**
- Убедись, что имя резолвится в **список Pod IP**, а не в VIP.
- Для именованных портов смотри SRV-записи: `_http._tcp.svc.ns.svc.cluster.local`.
