#sr-due 
1. Основная задача
	1. Следить, чтобы Job выполнился успешно нужное количество раз
	2. Создавать и пересоздавать Pod'ы до тех пор, пока не будет достигнуто .spec.completions
	3. Управлять параллельным выполнение задач
2. Как работает reconcile loop
	1. Informer следит за Job и его Pod'ами
	2. Контроллер проверяет:
		1. Сколько Pod'ов уже успешно завершилось (status.succeeded)
		2. Сколько Pod'ов в процессе (status.active)
		3. Сколько Pod'ов упали (status.failed)
	3. Сравнивает это с желаемым (status.completions, spec.parallelism)
	4. Действует:
		1. Если Pod меньше, чем нужно -> создаёт новые
		2. Если Pod слишком много -> удаляет лишние
		3. Если Pod упал -> решает, перезапустить или нет (по backofflimit)
	5. Обновляет .status у Job
3. Важные детали
	1. restartPolicy для Pod в Job -> только `Never` или `OnFailure`
	2. backoffLimit -> сколько раз пытаться перезапустить Pod, если он падает
	3. parallelism -> ограничивает, сколько Pod могут работать одновременно
	4. completions -> сколько успешных Pod нужно для завершения Job
	5. Если completions не указано -> по умолчанию = 1
	6. Если parallelism не указано -> по умолчанию = 1
4. Пример поведения
	1. completions=5, parallelism=2
	2. -> контроллер запускает по 2 Pod одновременно, пока не будет 5 успешных
	3. Pod упал -> контроллер пересоздаёт его, пока не достигнет backoffLimit
	4. Все Pod завершились успешно -> Job переходит в состояние Completed
