#sr-due 
Источник сигналов:
	Node level: kubelet + cAdvisor, kube-proxy, node-exporter
	Cluster level: kube-state-metrics (информеры поверх API)
	App Level: /metrics в сервисах (Prometheus Client), probes, app-логи
Сбор и агрегация:
	kubelet /stats/summary -> metrics-server (metrics api)
	Prometheus (scrape pull) <- ServiceMonitor/PodMonitor
	Логи: CRI -> files/journald -> Promtail/Fluent Bit -> Loki/ES
Экспозиция и интерфейсы:
	Kubernetes Aggregation Layer (apiserver + APIService)
	Promethes HTTP API, Loki API
Визуализация и реакция:
	Grafana (dashboards + logs explore)
	Alertmanager (routing, silences)

Почему так: Kubernetes даёт стандартизованные точки данных (metrics & summary в kubelet, статусы объектов через API), а экосистема Prometheus/Loki делает хранение, поиск, алерты и дашборды
