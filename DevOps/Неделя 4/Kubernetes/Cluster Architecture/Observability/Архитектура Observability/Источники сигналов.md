#sr-due 
Node level:
- kubelet (secure port 10250):
	- /metrics - метрики самого kubelet (Prometheus format)
	- /metrics/cadvisor - контейнерные метрики от встроенного cAdvisor
	- /stats/summary - агрегированное дерево ресурсов (CPU/Memory/FS/Network) для metrics-server
- kube-proxy: /metrics (ipvs/iptables counters, latency)
- node-exporter: системные метрики Linux (CPU, meminfo, disk, net)

Cluster Level:
- kube-state-metrics: через informer'ы watch'ит API, транслирует состояние объектов в метрики: Deployment replicas, Pod phase, Ready/NotReady, Node conditions и т.п.

App Level:
- /metrics в приложениях (Prometheus client libraries) - бизнес/технические метрики
- Probes (liveness/readiness/startup) - не метрики, а сигналы состотяния, влияющие на рестарты и маршрутизацию трафика
- Логи: stdou/stderr -> CRI пишет JSON-файлы в /var/log/pods/.. и /var/log/containers/*-namespace-pod-*.log (или journald)
