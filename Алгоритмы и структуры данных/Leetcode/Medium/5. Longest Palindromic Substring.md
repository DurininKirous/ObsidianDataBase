```go
func longestPalindrome(s string) string {
    maxS := ""
    for i := range s {
        l1, r1 := expand(s, i, i)
        l2, r2 := expand(s, i, i+1)
        if r1-l1+1 > len(maxS) {
            maxS = s[l1 : r1+1]
        }
        if r2-l2+1 > len(maxS) {
            maxS = s[l2 : r2+1]
        }
    }
    return maxS
}

func expand(s string, l, r int) (int, int) {
    for l >= 0 && r < len(s) && s[l] == s[r] {
        l--
        r++
    }
    return l + 1, r - 1
}
```
## Идея
**Расширение от центра (Expand Around Center):**  
Каждый палиндром полностью определяется своим центром. Центр бывает:
- один символ (нечётная длина): `(i, i)`
- «щель» между символами (чётная длина): `(i, i+1)`
Для каждого `i` расширяемся влево/вправо пока `s[l] == s[r]`. Максимум среди всех центров — ответ.  
Сложность: **O(n²)** по времени, **O(1)** по памяти.

---

## Подводные камни
- Возвращаемые индексы из `expand`: после цикла корректный палиндром — это **[l+1, r-1]**.  
    Значит функция должна вернуть **(l+1, r-1)** именно в таком порядке: `(left, right)`.
- Не путать порядок присваивания: `l1, r1 := expand(...)`, а не наоборот.
- `range s` по рунам, а индексация в `expand` по байтам. Для ASCII (LeetCode) ок. Для Unicode — конвертировать в `[]rune`.
