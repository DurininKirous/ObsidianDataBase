#sr-due 
```go
import "sort"

func combinationSum(candidates []int, target int) [][]int {
    sort.Ints(candidates)          
    res := [][]int{}
    findCombinations(0, candidates, target, []int{}, &res)
    return res
}

func findCombinations(sum int, candidates []int, target int, curr []int, result *[][]int) {
    if sum == target {
        comb := make([]int, len(curr))
        copy(comb, curr)
        *result = append(*result, comb)
        return
    } else if sum < target {
        last := -1
        if len(curr) > 0 {
            last = curr[len(curr)-1]
        }
        for _, val := range candidates {
            if last != -1 && val < last {
                continue
            }
            if sum+val > target {
                break
            }
            findCombinations(sum+val, candidates, target, append(curr, val), result)
        }
    }
    return
}
```
## Идея
- Классический **backtracking** для задачи «unbounded knapsack».
- Кандидаты сортируются один раз.
- Рекурсия строит комбинации суммой `sum` и текущим путём `curr`.
- Как только `sum == target` — копируем `curr` в результат.

## Как избегаются дубликаты
- Держим путь **неубывающим**: `last` — последний добавленный элемент.
- В цикле по кандидатам пропускаем все `val < last`.  
    Так комбинации типа `[2,3,2]` не рождаются — остаётся только `[2,2,3]`.

## Pruning (раннее отсечение)
- Кандидаты отсортированы → если `sum+val > target`, то все дальнейшие `val` будут лишь больше.  
    Поэтому делаем `break`, отрезая бесполезные ветки.
