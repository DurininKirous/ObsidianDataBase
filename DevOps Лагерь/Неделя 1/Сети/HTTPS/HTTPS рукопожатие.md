
## Первый этап
Устанавливается TCP соединение через [[Работа TCP (рукопожатие)]], потом поверх этого происходит установление защищённого соединения.

## Второй этап
После этого происходит обмен ClientHello и ServerHello "сообщениями".
Это по сути поток сырых байтов, который передаётся незащищённо. Данные там публичные либо рандомные и ценности для злоумышленника ключевой не несут. Типо аналога протокола Диффи-Хеллмана происходит.
### Структура ClientHello:

| Поле          | Что значит                          |
| ------------- | ----------------------------------- |
| Version       | Поддерживаемые TLS версии           |
| Random        | Случайные байты клиента             |
| Session ID    | Для Resumption                      |
| Cipher Suites | Какие шифры поддерживает клиент     |
| Compression   | Почти всегда null, с TLS не сжимают |
| Extension     | SNI, ALPN, Supported Groups         |
SNI (Server Name Indication) - указывает домен, для которого клиент хочет сертефикат
ALPN - для выбора HTTP/2, HTTP/1.1

### Структура ServerHello

| Поле          | Что значит                           |
| ------------- | ------------------------------------ |
| Version       | Какая TLS версия выбрана             |
| Random        | Случайные байты сервера              |
| Session ID    | Подтверждает/назначает сессию        |
| Chosen Cipher | Сервер выбирает шифр из предложенных |
| Extensions    | ALPN, OCSP Stapling, др.             |

## Третий этап

Сервер отправляет цепочку сертификатов:
 - Server Certificate (CN=ya.ru)
 - Intermediate CA
 - Root CA
Происходит последовательная проверка сертификатов сверху вниз:
Проверяется, выдан ли Server Certificate на данный сайт, подписан ли он, и кем подписан.
Если всё нормально, дальше проверяется Intermediate CA, подписан ли он и кем подписан.
Далее смотрят на Root CA, он не передаётся обычно никуда и только хранится на устройствах, поэтому созданы Intermediate CA. Обычно Root CA уже есть у пользователя в хранилище, ну и проверяют, есть ли он. Если есть, то проверка на данном этапе пройдена, в противном случае не доверяем цепочке.

## Четвёртый этап
На данном этапе при успешной проверке сертификатов происходит обмен ключами и установление защищённого соединения.
Этап 1: Обмен ключами
	Сервер прислал свой публичный ключ (ServerKeyExchange)
	 Клиент генерирует свой ключ
	 В ClientKeyExchange он шлёт его серверу
	 На этом этапе обе стороны независимо вычисляют shared secret:
	 Shared secret = f(серверный публичный ключ, клиентский приватный ключ)
             = f(клиентский публичный ключ, серверный приватный ключ)
Этап 2:
	Из shared secret + random'ов, обе стороны получают:
		Session key: для шифрования (AES,ChaCha20)
	Mac key: для проверки целостности
	IV: в зависимости от cipher
	
Этап 3: ChangeCipherSpec
	Клиент говорит: "Всё, теперь шифрую"
	И отправляет это сообщение
	
Этап 4: Finished
	Первое сообщение, зашифрованное session key
	Оно содержит весь mac на предыдущий handshake
	Если сервер видит правильный MAC, значит всё ок

Этап 5: Сервер в ответ:
	ChangeCipherSpec
	Finished (тоже зашифрован)

После этого уже передаётся зашифрованный трафик.

В TLS 1.3 попроще, там ClientHello идёт сразу с публичным ключом, а ServerHello идёт с ключом + пачкой сертификатов тех + финишем.
Дальше идёт финиш от клиента и трафик шифруется.
