#sr-due 
### Фильтрация
Оставляет только валидные Node'ы, где Pod в принципе может запуститься.
Примеры плагинов:

| Плагин                   | Проверяет                                        |
| ------------------------ | ------------------------------------------------ |
| `PodToleratesNodeTaints` | Есть ли у Pod `tolerations` к таинтам Node       |
| `NodeUnschedulable`      | Node не помечен как `unschedulable`              |
| `PodFitsResources`       | Есть ли свободные ресурсы на Node (CPU, Memory)  |
| `PodTopologySpread`      | Не нарушит ли балансировку по zone/hostname      |
| `NodeAffinity`           | Совпадает ли Node с affinity/selector'ом Pod’а   |
| `VolumeZone`             | Можно ли смонтировать volume (zone restrictions) |
| `VolumeBinding`          | Volume доступен с нужной Node                    |

### Скаринг
Каждой валидной ноде выставляется балл (0-100)

| Плагин               | Логика                                                 |
| -------------------- | ------------------------------------------------------ |
| `LeastRequested`     | Чем больше свободных ресурсов — тем выше балл          |
| `BalancedAllocation` | Баланс CPU и memory                                    |
| `NodeAffinity`       | Учитывает предпочтения affinity с весами               |
| `ImageLocality`      | Плюс, если нужный контейнер уже есть на Node           |
| `TopologySpread`     | Старается распределять Pod’ы равномерно по зонам/узлам |
| `InterPodAffinity`   | Располагает рядом с другими нужными pod’ами            |
Побеждает нода с максимальным баллом
