#sr-due 
1. Основная задача
	1. Управлять Pod'ами с уникальной идентичностью 
	2. Следить, чтобы у каждого пода был свой PVC
	3. Гарантировать порядок запуска и удаления Pod'ов
2. Как работает reconcile loop
	1. Informer следит за StatefulSet и его Pod'ами
	2. Контроллер сравнивает
		1. spec.replicas
		2. реальное количество Pod'ов
	3. Создаёт/удаляет Pod'ы, но строго по порядку:
		1. Сначала создаётся pod-0
		2. Только когда pod-0 running + ready -> создаётся pod-1
		3. И так далее
	4. При уменьшении `replicas` Pod'ы удаляются в обратном порядке
	5. Создаётся PVC на основе volumeClaimTemplates (Один PVC на Pod)
		1. PVC не удаляются, даже если удалён Pod -> сохраняется состояние
3. Отличительные особенности
	1. Стабильные имена Pod'ов: формируются как "statefulset-name-ordinal"
	2. Headless service: нужен для стабильных DNS-имён Pod'ов
	3. PVC привязан к Pod: при пересоздании Pod получает тот же PVC
	4. OrderedReady: Pod'ы запускаются и удаляются строго по порядку
	5. UpdatedStrategy:
		1. RollingUpdate: обновляет Pod'ы по одному, сохраняя порядок
		2. OnDelete: Pod обновится только если его удалить руками
4. Пример поведения
	1. Если Pod `web-0` упал -> StatefulSet Controller пересоздаст его с тем же именем и PVC
	2. Если уменьшить `replicas` с 3 до 2 -> удалится web-2, а web-0 и web-1 останутся
	3. Если увеличить с 2 до 3 -> создаст web-2
