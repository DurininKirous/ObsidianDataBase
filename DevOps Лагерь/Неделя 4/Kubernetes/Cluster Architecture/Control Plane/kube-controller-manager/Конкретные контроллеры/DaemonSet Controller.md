#sr-due 
1. Основная задача
	1. Следить, чтобы на каждой подходящей ноде работал Pod из DaemonSet
	2. Автоматически добавлять Pod при появлении новой ноды
	3. Удалять Pod при удалении ноды или изменении условий
2. Как работает reconcile loop
	1. Informer следит за DaemonSet'ами, Node'ами, Pod'ами
	2. Для каждого DaemonSet контроллер строит список нод:
		1. Все ноды кластера
		2. Отфильтровывает по nodeSelector, nodeAffinity, tolerations
	3. Сравнивает:
		1. На каких нодах Pod уже есть
		2. Где Pod не хватает
	4. Действия:
		1. Если Pod отсутствует на ноде ->  создаёт новый
		2. Если Pod лишний -> удаляет
		3. Если нода уходит -> Pod тоже удаляется
	5. Следит за стратегией обновлений:
		1. Обновляет Pod'ы по одной ноде за раз, чтобы не сломать кластер
		2. Можно переключить на onDelete (обновляется только если вручную удалить Pod)
3. Важные особенности:
	1. Нет .spec.replicas: количество Pod'ов = количество подходящих нод
	2. Node lifecycle: как только новая нода присоединилась к кластеру -> контроллер создаёт на ней под
	3. Selective placement: можно ограничить, на каких нодах будет DaemonSet 
	4. UpdateStrategy: 
		1. RollingUpdate -> по одной ноде
		2. OnDelete -> ручной контроль
4. Пример поведения:
	1. Добавил новую ноду -> автоматически поднимается Pod DaemonSet
	2. Поставил `nodeSelector: disktype=ssd` -> Pod запускается только на нодах с этим лейблом
	3. Обновил DaemonSet -> контроллер перезапускает Pod'ы по одной ноде
