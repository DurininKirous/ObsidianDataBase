#sr-due 

1. Событие (Add/Update/Delete) приходит из API-сервера в informer
2. Informer вызывает хендлер и кладёт ключ объекта в WorkQueue
3. Воркеры контроллера делают цикл:
	1. достают ключ
	2. вызывают reconcile(key)
	3. ошибка -> AddRateLimited(key) (будет повтор с задержкой)
4. После завершения всегда вызывается Done(key), чтобы ключ мог быть переиспользован

Важная деталь: если объект изменился, пока он в обработке, после Done ключ снова попадёт в очередь
