#sr-due 
Это - один из самых практичных механизмов продакшена. Он нужен, чтобы разделить кластеры по классам нагрузок (системные, критичные, spot? dev и т.д.) и гарантировать, что мусор или фоновые джобы не окажутся на прод-нодах.

Принцип работы:
- Taint (метка с "ядом") вешается на ноду. Если у пода нет подходящей Toleration (терпимости) - scheduler не положит его туда.
- Это противоположность label'ам: label - "куда можно", taint - "куда нельзя"

Формат taint'а
```
kubectl taint nodes <node> key=value:Effect
```
Effect может быть:

| Effect           | Поведение                                                           |
| ---------------- | ------------------------------------------------------------------- |
| NoSchedule       | Под не будет назначен на ноду                                       |
| PreferNoSchedule | "мягкий" вариант - scheduler старается избегать, но может назначить |
| NoExecute        | Существующие поды, не терпящие taint, будут выселены                |
