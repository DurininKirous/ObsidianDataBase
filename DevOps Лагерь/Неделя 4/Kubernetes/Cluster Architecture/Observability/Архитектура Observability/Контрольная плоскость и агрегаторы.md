#sr-due 
API Aggregation Later (в kube-apiserver):
- Позволяет "подшивать" внешние apiserver'ы как официальные группы:
	- metrics.k8s.io (даёт kubectl top и HPA cpu/memory через metrics-server)
	- custom.metrics.k8s.io (кастомные метрики)
	- external.metrics.k8s.io (внешние источники, KEDA и т.п.)
- Регистрация через объекты APIService. kube-apiserver выступает фронтом, проксируя запросы к задним apserver'ам

metrics-server:
- Переодически читает kubelet /stats/summary со всех нод
- Публикует в Aggregation Layer -> apis/metrics.k8s.io/
- Используется kubectl top и HPA (CPU/Memory targets)

kube-state-metrics:
- Не часть Aggregation Layer. Это обычный Deployment, экспонирующий /metrics (pull'ится Prometheus)
- Внутри: informer loop -> store -> преобразование в Prometheus гейджи/каунтеры по объектам
