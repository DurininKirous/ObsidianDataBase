#sr-due 
### cpu.max
- если процесс в этой cgroup за 100 мс уже использовал свои 50 мс, его просто **не планируют на CPU** (put on run queue with throttling).
- это значит: процесс **не убивается**, просто дальше сидит в `sleep`, ждёт пока не начнётся следующий период.
### memory.max
- когда процесс аллоцирует память (malloc / mmap / brk), ядро увеличивает usage счётчик.
- если из-за нового аллока процесс превысит `memory.max`, срабатывает **OOM-killer** — но он убивает **процесс внутри этой cgroup**, а не всей системы.
### io.max
- ядро в своём blkio scheduler замедляет обработку запросов этой cgroup.
- нет убийства процессов, просто throttling (как для CPU).
